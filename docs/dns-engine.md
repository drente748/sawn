# فلترة DNS عبر VPN — مواصفة

> مواصفة سلوك، **بلا تنفيذ**. المرجع لمرحلة التصميم وللتنفيذ لاحقاً.
> آخر تحديث: 2026-11-12 — بعد `d128d36`.

---

## 1. ما يفعله اليوم

| | |
|---|---|
| **النطاق** | مجرى محلّلات DNS فقط: `10.111.222.2/32` (v4) + `fd00:2024:1111:2222::1/128` (v6). **لا مرور غير DNS** — لا تصفّح ولا HTTP ولا أي شيء آخر |
| **الاستقبال** | محلّلات الجهاز الحقيقية تُلتقط **قبل**establish (بعدها يصبح الشبكة النشطة هي النفق)، مع بديل `1.1.1.1` إن لم يوفّر النظام أياً |
| **الحجب** | الاسم المحجوب → `0.0.0.0` (A) أو ردّ فارغ NOERROR (أنواع أخرى وAAAA) — والاسم يُطابَق مع نطاقاته الفرعية |
| **IPv6** | لا يُعطى أي عنوان AAAA حقيقي إطلاقاً (إجابة فارغة) — وإلا التفّ الفلتر على الشبكة المزدوجة |
| **SafeSearch** | **إعادة كتابة** لا حجب، وإن حجب المستخدم نفس الاسم فالحجب يسود |
| **DoH** | يُحجب **بالاسم** فقط؛ محلّلات بـIP مثبّت تتجاوزه |
| **العزل** | `addDisallowedApplication` — مرور صَوْن نفسه لا يمرّ في نفقها (فلنُصفّح قوائمنا عبر فلترنا) |
| **الإقلاع** | `setBlocking(true)` — النفق يحجب أثناء الإقلاع فلا يتسرّب مرور |
| **السقوط** | موت النفق = توقف الحماية → `GuardHealthWorker` يفحص كل ١٥ دقيقة (كل ٣ في الصارم) ويُشعر |
| **الخصوصية** | **لا يُسجَّل اسم أيّ موقع** — الاستعلامات تُمرَّر إلى محلّل الجهاز، لا إلى خوادمنا |

## 2. القرارات

| # | القرار | السبب |
|---|---|---|
| 1 | **لا مرور غير DNS** داخل النفق | لا تأخير ولا رؤية — والمرور يمرّ كما هو |
| 2 | **المحجوب يُجاب `0.0.0.0`** لا يُهدَم صامتاً | الفشل السريع أفضل من تعليق التطبيق على مهلة |
| 3 | **ردّ فارغ لـAAAA دائماً** | بدونه يمرّ جزء من الحركة حول الفلتر |
| 4 | **SafeSearch إعادة كتابة، وحجب المستخدم يسود عليها** | الترتيب يحترم قرار المستخدم |
| 5 | **لا سجلّ لأسماء المواقع** (لا تاريخ للمواقع) | الخصوصية:Flush DNS names = browsing history. يُبقى عدّاد الأحداث على مستوى التطبيقات فقط |
| 6 | **DoH يُحجب بالاسم** والحدّ (IP مثبّت) يُذكر في وصف الخيار | الشفافية قبل الوهم |
| 7 | **النطاقات الفرعية محجوبة** مع النطاق | سلوك متوقّع |
| 8 | **قائمة الاستثناءات الحرجة قصيرة ومُغلقة** (mtalk، connectivitycheck، time، clients3) | توسيعها = توسيع ثقب |
| 9 | **«الحماية المطلقة» تعيش في طبقة الوصول لا في DNS** | طبقة الوصول تعرف التطبيق الأمامي؛ DNS لا يعرفه — فحجب كل الأسماء يكسر الهاتف والخدمات المصرفية |
| 10 | **لا يُسجَّل ولا يُعرض ما حُجب على مستوى المواقع** | انظر 5 |

## 3. الفرق بين المحركين (هذا هو جوهر «الوضع المتقدم»)

| | فلترة DNS | محرك الوصول (المتصفح) |
|---|---|---|
| **يعمل على** | الأسماء | ما يُرى في شريط العنوان |
| **يصطاد** | كل متصفح، كل WebView، كل تطبيق | المتصفحات المعروفة فقط، وWebView لا |
| **يحجب قوائم المدمجة** | نعم (مفاتيحها) | نعم (نفس القائمة) |
| **يحتاج إذن VPN** | نعم | لا |
| **سجلّ ما حُجب** | لا | لا |
| **أثره على السرعة** | لا (DNS فقط) | لا |

**النتيجة**: فلترة DNS هي **الأقوى**؛ وضعها المتقدّم يعني «الكل». والوضع الخفيف اختيار
عملي: بلا إذن VPN، مع تغطية أضيق.

## 4. ما يجب أن تعرضه الواجهة

| الموضع | المحتوى |
|---|---|
| **الشارة** | أيّ طبقة تعمل **فعلاً** (لا ما في الإعدادات) |
| **إشعار النفق** | دائم، يذكّر بأن الفلترة تعمل + كيف تُغلق |
| **وصف مفتاح DoH** | «يُحجب بالمُضيف فقط — محلّلات بـIP مثبّت تتجاوزه» |
| **فحص الحماية** | «فلترة DNS: تعمل / لا يعمل (بلا إذن) / متوقفة» |
| **عند إطفاء العامّ** | «العناصر ذات القاعدة تبقى محجوبة» (من قاعدة العنصر) |

---

## 5. ما لا يتغيّر

- القوائم المدمجة (بالغين/إعلانات/DoH) عامّة، بلا قاعدة لكل عنصر.
- الاستثناءات الحرجة على مستوى التطبيقات (`CriticalApps`) لا تمسّ هذه الطبقة — هي
  طبقة أسماء.
- خيار «بلا إذن VPN» (الوضع الخفيف) يبقى موجوداً: وضع بلا إذن **مكمّل** لا عيب.
